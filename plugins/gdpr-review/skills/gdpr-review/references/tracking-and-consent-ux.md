# Tracking & Consent UX — ePrivacy adjacency, dark patterns

Cookie/tracker consent is technically the ePrivacy Directive (Art. 5(3)) with
GDPR-standard consent; IDs here use the `EPRIV-` prefix. Dark-pattern consent is
an active DPA enforcement target. A pending EU proposal would fold cookie
consent into GDPR proper — **verify current status live** if a finding turns on
which instrument applies.

Columns: **ID** · **Requirement** · **Automated signal** · **Domain** · **Type**.
Type semantics as in `lawful-basis.md`.

## Script & cookie gating

| ID | Requirement | Automated signal | Domain | Type |
|----|-------------|------------------|--------|------|
| EPRIV-5.3-GATE | Non-essential scripts load only after opt-in | Hardcoded `<script src>` to analytics/pixel/session-replay vendors (GA/gtag, Meta Pixel, Hotjar, TikTok, etc.) loaded unconditionally instead of behind a CMP callback / consent-mode gate | 7 | technical |
| EPRIV-5.3-SET | Non-essential cookies not set before consent | Cookies/localStorage identifiers written on first paint pre-consent | 7 | technical |
| EPRIV-5.3-CLASS | Cookies classified essential vs non-essential honestly | "Essential" bucket containing analytics/marketing cookies = finding | 7 | technical |

## Banner & withdrawal UX (dark patterns)

| ID | Requirement | Automated signal | Domain | Type |
|----|-------------|------------------|--------|------|
| EPRIV-UX-REJ | Reject as easy as accept | First-layer "Reject all" with prominence equal to "Accept all"; reject buried in a second layer = finding | 7 | technical |
| EPRIV-UX-NUDGE | No manipulative design | Color/size asymmetry pushing accept, guilt-wording, consent fatigue via re-prompt loops after rejection | 7 | technical |
| EPRIV-UX-WDRW | Withdrawal reachable post-choice | Persistent settings entry point to change/withdraw; withdrawal takes effect (scripts stop firing) | 1,7 | technical |
| EPRIV-GPC | Global Privacy Control honored | `navigator.globalPrivacyControl` / `Sec-GPC` header read and applied | 7 | technical |
